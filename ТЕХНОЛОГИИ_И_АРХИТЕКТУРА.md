# Технологии, сервисы и архитектура проекта «Матрица компетенций»

## 1) Назначение проекта

Проект реализует систему управления задачами и компетенциями сотрудников:
- менеджер создает и распределяет задачи;
- сотрудник видит свои задачи, рекомендации и подает заявки на задачи;
- система учитывает роли, навыки, статусы задач, уведомления и профиль сотрудника;
- аналитический контур поддерживается через BI-дашборды.

## 2) Технологический стек

### Backend / API
- `Python`
- `FastAPI` — основной REST API (`fastapi_app`)
- `SQLAlchemy` (async) — ORM и работа с БД
- `asyncpg` / `aiosqlite` — драйверы БД
- `Pydantic` — схемы и валидация данных
- `JWT`-аутентификация (секрет в `JWT_SECRET`)

### Legacy / Auth Web
- `Flask` (`flask_auth`) — отдельный веб-модуль логина/регистрации и перехода в Superset
- `bcrypt` — хеширование паролей
- `psycopg2` — доступ к PostgreSQL в Flask-модуле

### Mobile
- `React Native` + `Expo` (`mobile-app`)
- `expo-router` — маршрутизация
- `@tanstack/react-query` — клиентский data-fetching и кэш
- `TypeScript`

### Data / ETL / Orchestration
- `Apache Airflow` (`airflow`) — оркестрация процессов
- `dbt` (`dbt/my_matrix`) — трансформации и модели данных
- `pandas`, `openpyxl`, `paramiko`, `python-dotenv` (`parser`) — загрузка данных из Excel/по SSH

### BI / Кэш / Инфраструктура
- `PostgreSQL 15` — основное хранилище
- `Redis 7` — кэш/служебные задачи
- `Apache Superset` — визуализация и дашборды
- `Docker` / `Docker Compose` — контейнеризация всех сервисов

## 3) Сервисы в `docker-compose`

Основные контейнеры:
- `db` — PostgreSQL
- `af` — Airflow (web + scheduler в режиме standalone)
- `dbt` — запуск dbt-пайплайна
- `fastapi` — API приложения
- `redis` — инфраструктурный кэш
- `superset-init` — инициализация Superset (миграции, admin, init)
- `superset` — BI-приложение

Сеть:
- единая bridge-сеть `my-network` для межсервисного взаимодействия.

Volumes:
- `postgres_data`, `redis`, `superset_home` для персистентности данных.

## 4) Архитектура приложения (логическая)

### 4.1 Клиентский слой
- `mobile-app` (Expo) — основной пользовательский интерфейс для сотрудников и менеджеров.
- `flask_auth` — веб-страница входа/регистрации и вход в BI-панель.

### 4.2 API-слой
- `fastapi_app`:
  - маршруты (`routers/*`) — auth, сотрудники, задачи, уведомления;
  - бизнес-логика (`services/*`) — рекомендации, подбор, доменные операции;
  - модели (`models.py`) и схемы (`schemas.py`);
  - стартовая инициализация (`main.py`) — миграции/создание таблиц/seed/bootstrap.

### 4.3 Слой данных
- Операционные таблицы для пользователей, задач, компетенций и связей.
- Legacy-таблицы в схеме `dev.*` (для совместимости и интеграции).
- Служебные таблицы статусов задач, отпусков, запросов навыков, уведомлений.

### 4.4 Аналитический слой
- Airflow запускает загрузку и обновление данных.
- Parser забирает исходные данные из Excel.
- dbt строит модели/витрины для анализа.
- Superset показывает дашборды руководителям и аналитикам.

## 5) Архитектурный стиль

Проект использует гибридный подход:
- `Monorepo` с несколькими приложениями (API, mobile, ETL, BI, legacy web);
- `Service-oriented` инфраструктура (контейнеры по ролям);
- `Layered architecture` внутри FastAPI (router -> service -> model/repository);
- частичная `legacy compatibility architecture` через таблицы `dev.*`.

## 6) Потоки данных (end-to-end)

### Поток A: Бизнес-пользователь
1. Пользователь логинится в мобильном приложении.
2. Mobile обращается к `FastAPI`.
3. FastAPI читает/обновляет данные в PostgreSQL.
4. Пользователь получает задачи, рекомендации, уведомления, профиль.

### Поток B: Менеджер и аналитика
1. Менеджер работает с задачами и командой через mobile/API.
2. Данные накапливаются в PostgreSQL.
3. Airflow + dbt подготавливают аналитический слой.
4. Superset читает витрины и отображает дашборды.

### Поток C: Импорт данных
1. Parser получает Excel-источники.
2. Загружает данные в PostgreSQL (`dev.*` и связанные таблицы).
3. FastAPI при старте синхронизирует/нормализует структуры (включая fallback/legacy логику по настройкам).

## 7) Безопасность и доступы (текущая реализация)

- Ролевая модель: `manager` / `employee`.
- JWT-токены для доступа к API.
- Пароли хранятся в виде хеша (`bcrypt`).
- Секреты и переменные окружения вынесены в `.env`.

## 8) Отказоустойчивость и эксплуатация

- Контейнеризированный запуск через Docker Compose.
- Для FastAPI предусмотрен режим без SQLite fallback в production (`ALLOW_SQLITE_FALLBACK=false`).
- Инициализация сервисов и БД автоматизирована стартовыми командами контейнеров.

## 9) Структура репозитория (укрупненно)

- `fastapi_app` — основной backend
- `mobile-app` — мобильный клиент
- `flask_auth` — веб-авторизация и вход в BI
- `airflow` — DAG-оркестрация
- `dbt` — модели трансформации
- `parser` — импорт исходных данных
- `docker`, `postgres` — инфраструктурные и init-скрипты
- `tests` — тесты

## 10) Краткий итог

Проект построен как единая платформа управления компетенциями, где:
- операционный контур — `Mobile + FastAPI + PostgreSQL`;
- интеграционный контур — `Airflow + Parser + dbt`;
- аналитический контур — `Superset + PostgreSQL`;
- поддержка legacy-сценариев обеспечивается отдельным `Flask`-модулем и `dev.*` таблицами.
